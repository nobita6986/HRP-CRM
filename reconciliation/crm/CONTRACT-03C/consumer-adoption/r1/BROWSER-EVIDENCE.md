# BROWSER EVIDENCE

## Method

Per the r2 plan MIGRATION-SEQUENCE.md M5 section, the Playwright
browser suite was actually executed (not just build-only). Steps:

1. Built `apps/context-panel` (`npm run build` including the UI bundle
   via `npm run build:ui`).
2. Booted `apps/context-panel` with:
   ```
   HRP_LISTEN_HOST=127.0.0.1
   HRP_LISTEN_PORT=15501
   NODE_ENV=development
   HRP_MOCK_MODE=deterministic
   HRP_ALLOW_DEV_TOOLS=true
   node dist/server.js
   ```
3. Ran the four Playwright evidence scripts:
   - `tests/browser-evidence.mjs`
   - `tests/routing-browser-evidence.mjs`
   - `tests/assistant-browser-evidence.mjs`
   - `tests/dashboard-browser-evidence.mjs`
4. Confirmed `chromium.launch({ headless: true })` succeeds (Playwright
   + bundled Chromium).
5. Stopped the server.

## Asset 404s

The r2 plan calls for accurately classifying any pre-existing asset
404s in the scratch harness. No new asset 404s were observed in the
Playwright runs; the existing evidence PNGs in
`apps/context-panel/tests/evidence/` were regenerated by the harness
and remain consistent with the baseline asset expectations.

## No product changes to mask failures

No product code was edited to obtain a green browser label. The two
PRE_EXISTING context-panel `manifest-readonly` `--verify` failures
were NOT classified as browser failures — they are part of the unit
test suite (Node `node:test`) and run outside the Playwright harness.
They are documented in `TEST-EVIDENCE.md` as PRE_EXISTING.
